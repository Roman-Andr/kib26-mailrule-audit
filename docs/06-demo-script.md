# Сценарий демонстрации (3–5 минут)

Формат: запись экрана без лица, голос за кадром. Разрешение 1920×1080,
шрифт интерфейса увеличен, окно браузера — только приложение, без личных
вкладок и уведомлений. В кадр не попадают реальные адреса и переписка:
используются только файлы из `data/synthetic/`.

## Тайминг

### 0:00–0:30. Проблема

Говорим: малая компания без отдела ИБ, почта в облаке. После захвата ящика
злоумышленник не ломает защиту — он ставит правило пересылки и правило,
которое убирает письма банка из «Входящих». Компания узнаёт о краже по факту
платежа.

На экране: слайд 1 или титул приложения.

### 0:30–1:00. Что делает продукт

Говорим: на вход — выгрузка правил ящика, на выход — понятный отчёт с баллом,
приоритетом и действиями. Семь детекторов, только защитная логика, только
синтетические данные.

На экране: `README.md`, раздел «Что делает MVP», затем список файлов
`data/synthetic/`.

### 1:00–2:30. Демонстрация на «грязном» кейсе

1. Открываем `streamlit run app/ui.py`.
2. Выбираем `case-10.json` — «банковские слова, пересылка, без копии, ночная
   сессия без MFA».
3. Показываем: вердикт «Критично», 100 из 100, действия по порядку, таблицу
   находок с приоритетами.
4. Раскрываем исходный JSON: показываем правило `R-111` — видно, что все пять
   находок выведены из двух полей правила и одной сессии.
5. Скачиваем markdown-отчёт, открываем его в редакторе на 5 секунд.

### 2:30–3:15. Демонстрация на «чистом» кейсе

1. Выбираем `case-13.json` — автоответ и сортировка рассылок.
2. Показываем «Признаков захвата нет», 0 из 100 и объяснение, что именно
   проверялось.
3. Проговариваем ограничение: отчёт не гарантирует отсутствие взлома, он
   проверяет только правила, сессии и делегирования.

### 3:15–3:50. Надёжность и безопасность

1. Показываем терминал: `pytest -q` → 101 тест, включая проверку с
   заблокированной сетью.
2. Показываем `docs/05-testing.md`: 20 из 20 верных вердиктов, 0 ложных
   срабатываний.
3. Одна фраза про threat model: что учтено и что осталось за границами.

### 3:50–4:20. Итог и планы

Говорим: MVP решает узкую задачу — увидеть следы захвата ящика до платежа.
Дальше: поддержка реальных форматов экспорта, история проверок, интеграция с
журналом платежей.

На экране: слайд 5, ссылка на репозиторий.

## Чек-лист записи

- [ ] Запись в 1080p, 30 кадров, без рывков.
- [ ] Звук записан отдельно или через микрофон, без эха и щелчков.
- [ ] Нет личных данных: ни почты, ни мессенджеров, ни уведомлений.
- [ ] Интерфейс на русском, размер шрифта читается на телефоне.
- [ ] Длительность 3–5 минут, проверить таймером.
- [ ] Видео загружено, ссылка доступна по просмотру (не по запросу).
- [ ] Ссылка вставлена в реестр (колонка «Демо») и в README.

## Что сказать одной фразой, если спросят «чем это лучше антиспама»

Антиспам смотрит на письмо, а мы смотрим на настройки ящика: правило
пересылки может существовать месяцами и рассылать письма, не оставляя
подозрительных писем в «Входящих».
