# Декларация использования ИИ

Проект KIB-26 «Пиксель», блок 2. Документ фиксирует, где применялись
генеративные инструменты, что делал человек и как проверялся результат.

## 1. Какие инструменты использовались

| Инструмент | Версия/режим | Для чего |
|------------|--------------|----------|
| Ассистент на базе модели DeepSeek (deepseek-flash) в среде DeepSeek Harness | чат-агент с доступом к файлам репозитория | черновики документов, каркас кода, тесты, вычитка |
| Встроенные средства IDE | — | запуск тестов, форматирование, поиск по репозиторию |

ИИ не использовался для генерации источников: все 15 первоисточников блока 1
найдены и прочитаны людьми.

## 2. Где применялось

| Этап | Что сделал ИИ | Что сделал и проверил человек |
|------|----------------|-------------------------------|
| Регистрация темы | черновик формулировки темы и ключевых слов | капитан проверил уникальность, заполнил реестр, отправил на проверку |
| Банк знаний | — | студенты отобрали источники, написали карточки, указали метаданные |
| Problem statement | структура документа, черновые формулировки | авторы сверили каждую цифру с источником SRC-088…SRC-102 |
| Матрица аналогов | черновик таблицы критериев | исследователь проверил функции продуктов по официальным страницам |
| MVP | каркас парсера, детекторов, скоринга, отчёта, UI | капитан прочитал код, прогнал тесты, исправил логику детекторов |
| Тесты | набор юнит- и security-тестов | запуск, разбор падений, исправление ложного срабатывания |
| Документация | черновики `docs/03`, `docs/05`, `docs/06` | команда проверила факты и формулировки, утвердила тексты |
| Демо и защита | план сценария видео | запись и озвучка — людьми |

## 3. Как проверялся результат

1. **Цифры.** Каждое числовое утверждение в документах сопоставлено с
   первоисточником из банка знаний; при расхождении утверждение убиралось.
2. **Код.** Всё, что сгенерировано, проходит 101 тест, включая проверку
   отсутствия сетевых вызовов и экранирования разметки.
3. **Логика.** Правила детекторов описаны словами в README и в отчёте; если
   описание не совпадает с поведением, тест падает.
4. **Тексты.** Документы вычитаны людьми: убраны общие фразы, добавлены
   конкретные ограничения продукта.

## 4. Риски передачи данных

- В модель **не передавались** реальные выгрузки почты, адреса сотрудников,
  пароли, ключи и персональные данные.
- Использовались только: публичные отчёты вендоров из банка знаний,
  синтетические конфигурации из `data/synthetic/` и текст самого репозитория.
- Синтетические адреса и домены вымышлены (`pixel-smb.by`, `mail.ru`,
  `yandex.ru` как внешние адреса-примеры).
- Ответственность за содержание документов и кода несёт команда: ИИ —
  инструмент подготовки черновика, а не источник фактов.

## 5. Ограничения подхода

- ИИ склонен добавлять правдоподобные, но непроверенные цифры — поэтому в
  документах нет утверждений без ссылки на источник.
- Сгенерированный код может быть избыточным; итоговый вариант сокращён до
  функций, которые покрыты тестами.
- Ни один раздел не сдавался без человеческой вычитки.
