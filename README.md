# KIB-26 «Пиксель» — аудитор правил почтового ящика

Учебный проект по курсу «Основы кибербезопасности», блок 2.
Тема: выявление скрытой пересылки и сокрытия писем после захвата учётной
записи в малом и среднем бизнесе.

## Проблема

После захвата почтового ящика злоумышленник редко действует «в лоб». Он
ставит правило пересылки на внешний адрес и правило, которое убирает письма
банка и контрагентов из «Входящих», чтобы владелец не заметил переписку.
Компания узнаёт об этом по факту мошеннического платежа. В МСБ на 10–50
человек нет ни отдела ИБ, ни расширенных тарифов защиты почты, поэтому
проверить конфигурацию ящика некому.

## Что делает MVP

Приложение принимает JSON-экспорт правил ящика, сессий и делегирований,
находит подозрительные настройки и отдаёт отчёт: риск-скор 0–100, приоритет,
объяснение и рекомендацию для неспециалиста.

Семь детекторов:

| Детектор | Что ищет | Вес |
|----------|----------|-----|
| `EXT_FORWARD` | пересылка на адрес вне домена компании | 35 |
| `FORWARD_NO_COPY` | пересылка без сохранения копии, forward-and-delete | 25 |
| `EXT_DELEGATION` | доступ к ящику выдан внешнему адресу | 30 |
| `HIDDEN_FOLDER` | письма переносятся в папку вне «Входящих», часто с отметкой «прочитано» | 20 |
| `FINANCE_TARGET` | фильтр по словам «банк», «платёж», «счёт», invoice, договор в связке с пересылкой или сокрытием | 15 |
| `RISKY_SESSION` | правило создано из сессии без MFA или из нетипичной страны | 15 |
| `OFF_HOURS_RULE` | правило создано в нерабочее время или в выходной | 10 |

Балл правила — сумма весов находок (не больше 100). Итоговый балл — худшее
правило плюс 10 за каждое дополнительное правило с баллом 40 и выше.
Вердикты: «Признаков захвата нет» (0), «Низкий риск» (1–29), «Средний
риск» (30–59), «Высокий риск» (60–84), «Критично» (85–100).

## Быстрый старт

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# отчёт по одному кейсу в терминал
python -m app.cli --input data/synthetic/case-10.json

# JSON-отчёт в файл и код возврата 3 при находках
python -m app.cli --input data/synthetic/case-10.json --format json --out report.json --check

# веб-интерфейс
streamlit run app/ui.py

# тесты и пересоздание набора данных
pytest -q
python scripts/gen_configs.py
```

## Деплой в облако

Приложение готово к Streamlit Community Cloud: зависимости описаны в
`requirements.txt`, точка входа — `app/ui.py`, секретов и внешних сервисов нет.

1. Открыть share.streamlit.io и войти через GitHub (нужны админ-права на
   репозиторий).
2. Для приватного репозитория выдать приложению OAuth-скоуп `repo`: Cloud
   создаст read-only deploy key и получит доступ только на чтение.
3. New app → «Yup, I have an app» → репозиторий
   `Roman-Andr/kib26-mailrule-audit`, ветка `main`, файл `app/ui.py`.
4. В Advanced settings выбрать Python 3.11.
5. Deploy. Первый старт занимает пару минут; после долгой паузы приложение
   засыпает и просыпается при открытии ссылки.

Что важно помнить про облачную версию:

- загруженный JSON обрабатывается на сервере Streamlit, а не на машине
  пользователя, поэтому в облако загружаются только файлы из
  `data/synthetic/`, реальные выгрузки почты — никогда;
- бесплатный тариф даёт публичную ссылку: приложение может открыть любой, у
  кого она есть, но ничего не сохраняет — состояние живёт в рамках сессии.

## Безопасность и ограничения

- Только синтетические данные: реальные выгрузки почты не используются.
- Никаких сетевых вызовов и обращений к живым сервисам.
- Инструмент защитный: он читает конфигурацию, но не создаёт и не меняет
  правила, не удаляет письма и не снимает делегирование.
- Отчёт не является гарантией отсутствия взлома: проверяются только правила,
  сессии и делегирования из выгрузки. Что осталось за границами — описано в
  `docs/03-threat-model.md`.
